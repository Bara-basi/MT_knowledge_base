# MTSCO 企业内部知识库 v0.1 设计方案

## 1. 核心目标

本方案面向企业内部，重点解决以下两类问题：

1. **入职相关答疑**：覆盖上班时间、考勤方案、时间管理等高频问题。
2. **知识类问答**：覆盖部分公司背景知识与行业专业知识，例如基础业务概念、产品术语等。

## 2. 总体方案

项目最终形态是在飞书中开放一个所有公司员工都可以访问的 **AI 同事**。员工可以通过自然语言提问，系统根据企业知识库内容完成检索、理解与回答。

初版优先基于低代码平台 **n8n** 搭建工作流。n8n无法满足的部分，再考虑使用后端python处理

### 2.1 初版范围与边界

v0.1 版本优先验证“员工自然语言提问 -> 知识库检索 -> 生成可靠回答”的主链路能否跑通，不追求一次性覆盖所有内部资料。

初版暂不重点解决：
1. 全公司所有历史文档的完整入库。
2. 视频、音频等复杂资料的处理和自动化解析。
3. 报价、其它部门业务（财务、销售）等场景。
4. 暂不考虑数据权限问题，后期根据需求添加

## 3. 技术方案

### 3.1 技术选型

| 模块 | 初版方案 | 后续扩展 |
| --- | --- | --- |
| 工作流编排 | 优先使用 n8n 工作流 | 将 Python 后端能力抽象为工作流节点，由 n8n 调用 |
| 知识库来源 | 飞书知识库（通用知识部分） | 根据数据后端数据库质量与解析效果，引入自建向量知识库 |
| 后端服务 | python fastapi | 使用 FastAPI 暴露向量入库、向量检索等接口 |
| 向量存储 | 后端向量库 | 使用 Milvus 存储文本分块后的向量数据 |



### 3.2 Python 后端方案

搭建 Python 后端作为知识库服务，主要能力包括：

1. 对原始文档进行清洗、切分与结构化处理。
2. 使用 Milvus 存储文本分块后的向量数据。
3. 使用 FastAPI 暴露向量入库、向量检索等接口。
4. 将后端能力封装为可被 n8n 工作流调用的服务节点。

## 4. Agent 流程设计

### 4.1 问题类型

初版 Agent 主要面向三类通用问答场景：

| 类型 | 示例 |
| --- | --- |
| 流程问答 | 入职办理流程、新员工知识学习流程等 |
| 常见信息查询 | 上下班时间、如何打卡等 |
| 专业知识问答 | 无缝管、法兰等概念解释 |

在收到用户问题后，Agent 需要先进行意图识别，再根据问题类型选择合适的检索与回答策略。

### 4.2 输入处理

实际使用中，用户输入可能存在以下情况：

- 表达口语化，问题不够完整。
- 多轮对话中省略主语或上下文信息。
- 问题中包含图片等非纯文本内容。

Agent 在进入知识库检索前，需要对用户提问进行基础转写，对图片进行分析，尽量将问题整理为清晰、完整、可检索的查询语句。

### 4.3 最简流程


n8n工作流1(问答分流)
`webhook（用户query） -> query转写 -> 意图识别 -> 根据问题类别不同的工作流`

n8n工作流2、3(流程/知识问答工作流)
`用户query -> 向量召回 -> 生成答案 -> 幻觉率、准确性校验-> 回答`

n8n工作流4（查报价工作流，最后做）
`用户query -> 向量召回+读取报价规则汇总资料 -> mcp工具/本地函数接口计算价格 -> 验算/模型幻觉校验 -> 回答`

python端接口1(文档归一化)
`将多种模态数据统一转化为md文件（分类后，先使用开源库后规则提取） -> 按照先段落大意,后根据章节等结构裁切，最后按照字符数强制切割 -> 向量化，入库`

python端接口2(问答检索)
`query向量化 -> BM25+向量混合检索 -> 重排 -> 返回召回结果`

python端功能3(数据样例测试)
`针对每份文档生成问答对->测试召回率和全链路准确率 -> 给出统计结果和报表`

后续将根据实际情况和需求动态做出变更

## 5. 关键难点

### 5.1 输入模态复杂

知识库数据可能来自 PDF 扫描件、视频、音频、图片等多种模态，数据离散化难度较高。不同类型的数据需要采用不同的清洗、解析与分块策略。


### 5.2 富文本内容解析难度较高

飞书知识库中的文档多为富文本内容，例如：

- 教程文档中包含大量图片指引。
- 表格中存在人工填写的数据。
- 表格内可能包含大量空行与空白单元格。

这些内容会影响知识解析、文本切分和检索召回效果，目前以pdf/word等文件处理为主，后续逐渐引入更多模态。

### 5.3 权限分级（待定）
公司内部的部分信息只对高层可见，这导致信息需要做权限分级，模型不可使用无权限的数据作答


## 6. 分工规则

为充分利用个人特长，倩茹将**不参与**代码开发和工作流编排任务，主要负责数据整理与业务理解，包括：

1. 不同模态数据的分类与整理。
2. 业务内容的分类与梳理。
3. 知识库素材的初步清洗与结构化。

前期任务应主要集中在 n8n 工作流搭建上，包括：

1. 组织知识库内容，即飞书知识空间。
2. 编排并调试 n8n 工作流。
3. 接入飞书进行测试。
4. 优先跑通主要链路。

在主要链路跑通后，再继续强化知识库质量、完善校验系统，并逐步提高问答准确率。

## 7. 实施阶段规划

| 阶段 | 目标 | 主要任务 | 交付成果 | 预计时间|
| --- | --- | --- | --- |---|
| P0：链路验证 | 跑通最小可用问答链路 | 搭建 n8n 工作流、接入飞书、整理少量高频知识 | 可测试的 Demo | 2周 |
| P1：知识库增强 | 提高召回与回答准确率 | 文档清洗、分块、向量检索、重排 | 稳定问答流程 | 1个月 |
| P2：问答质量校验 | 降低错误回答和幻觉 | 答案校验、内部反馈收集 | 内部试用版本 | 1个月，后期需要持续维护 |
| P3：业务扩展 | 接入报价、销售等复杂业务 | 知识库数据整理，针对业务给出额外代码分支 | - | 计划1-1.5个/月扩展一项业务 |

## 8. 验收标准

v0.1 版本建议以以下标准作为初步验收依据：

1. 能在飞书中完成员工提问与系统回答。
2. 能覆盖入职、考勤、基础制度等高频问题。
3. 能够对知识库中明确不涵盖的提问拒答而不是出现幻觉。
5. 内部测试问题集的回答准确率达到可接受水平(80%以上)。
