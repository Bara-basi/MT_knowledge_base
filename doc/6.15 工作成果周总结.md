# 6.15 工作成果周总结

## 一、本周总体结论

本周已完成企业知识库一阶段核心目标：多格式文档入库、知识检索优化、模型回答优化、问答评估闭环和前端反馈能力均已落地。当前整体检索与回答效果较前期明显提升，已基本满足一阶段准确率目标。

目前仍需重点补齐三类能力：全量测试与压力测试、知识来源链接打通、回答速度优化。计划在本周内完成主要收尾工作，并在下周三前完成一阶段交付和权限开放。

## 二、本周完成内容

| 工作分类 | 完成内容 | 当前效果 |
|---|---|---|
| 知识库数据追加 | 完成 xlsx、pptx、结构化 PDF 等多格式文档解析与入库 | 已完成一阶段入库目标，知识库检索效果整体良好 |
| 知识检索优化 | 删除、切分、合并极端大小的知识切块；增加无效字符和表情字符清洗；移除对问答没有实际意义的链接 | 少量知识仍存在“已入库但检索不到”的情况，但整体召回率已大幅提升 |
| 模型回答优化 | 反复校准问答提示词和意图识别提示词 | 模型可根据问题难度调整回答篇幅，同时降低了拒答率 |
| 自定义高频词库 | 收集并构建企业内部专业术语，以及与企业强相关的人名、地名、公司名称等词库，避免分词阶段将专有名词打散 | “一书一课”“酷学院”“鸿迪”“沪新”等生僻词汇的召回率明显提升 |
| 问答数据集构建与使用 | 针对每份文档生成 5-10 个题目，每次抽样 10 题让模型回答，并自动评估回答质量；根据回答结果反哺系统优化 | 暂未完成全量测试，但从抽样准确率看，已达到一阶段准确率目标 |
| 界面优化 | 增加 n8n 轮询能力，并根据不同处理阶段给出反馈文案 | 用户等待过程中的状态感知更清晰 |
| 证据溯源 | 模型已能给出引用链接，后端已支持链接处理与结果排序 | 链接访问链路尚未打通，还需补充文件访问接口，或维护本地文件与飞书云文档的映射表 |
| 飞书 Markdown 功能 | 将原手动处理 Markdown 的方案调整为飞书 JSON 2.0 接口，减少大量手动转义工作 | 少量 Markdown 渲染仍不稳定，已对异常场景回退为手动处理 |
| Bug 修复 | 修复表格图片在代码处理过程中丢失的问题，并修复少数图片与实际图片描述不对应的问题 | 表格和图片类知识的处理稳定性提升 |
